** Per docs/syntax/named-subquery.md: A named subquery block that declares SELECT * (or SELECT DISTINCT * / SELECT REDUCED *) is not supported by the rewrite tool. It cannot be safely translated and so the rewrite is terminated. Why? When a named subquery is referenced via INCLUDE, the rewriter has to wrap that reference as { SELECT <vars> WHERE { INCLUDE %name } }, where <vars> is the block's explicit projected-variable list. With SELECT *, there is no explicit list to hoist — the rewriter would have to infer the projected variables from the subquery's pattern, and that inference isn't safe/guaranteed to match what QLever's own *-expansion would produce, so the rule refuses rather than risk a silently wrong rewrite.

Fix: replace SELECT DISTINCT * with an explicit projection listing the variables your subquery actually needs in the outer query.
